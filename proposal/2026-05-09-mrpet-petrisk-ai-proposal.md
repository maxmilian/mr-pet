## 一、專案概述

Mr.Pet × PetRisk.AI 是一個**人寵健康 AI 生態系**，分為兩大子系統：

| 系統 | 定位 | 目標用戶 | 網域 |
|------|------|----------|------|
| **Mr.Pet** | 電商平台 + 飼主端 | C 端飼主 | `mrpet.tw` |
| **PetRisk.AI** | 獸醫端 SaaS + AI 輔助診斷 | B 端獸醫診所 | `vet.mrpet.tw`（子網域） |

兩套系統採**子網域獨立部署**，透過 **SSO 單點登入**與 **PetPoint 紅利積分**跨系統連動，資料層完全隔離以確保醫療個資安全。

## 二、系統架構總覽

參見：[architecture-proposal.html](../architecture-proposal.html)

### 2.1 架構原則

1. **獨立部署**：Mr.Pet 與 PetRisk.AI 為兩套獨立系統，未來可完全拆站
2. **SSO 串接**：飼主可用同一組帳號（LINE / Google / Apple）跨系統登入
3. **去識別化**：獸醫可查看病患病歷，但無法得知其他診斷醫師身分
4. **多租戶隔離**：每間獸醫診所擁有獨立 Workspace，資料互不穿透
5. **資訊隔離**：醫療個資與電商資料分開儲存，符合 ISO 27001 規範

### 2.2 技術棧

| 層級 | Mr.Pet (C端) | PetRisk.AI (B端) |
|------|-------------|------------------|
| **前端** | Next.js 15 + Tailwind CSS (PWA) | Vue 3 / React + Tailwind (Desktop) |
| **後端** | FastAPI / Node.js | Python FastAPI |
| **資料庫** | Cloud SQL PostgreSQL | Cloud SQL PostgreSQL + PGVector |
| **AI** | — | Google Vertex AI (影像分析) |
| **檔案儲存** | — | Google Cloud Storage (醫療影像) |
| **快取** | Redis (PetPoint) | Redis |
| **部署** | Cloud Run / GKE | Cloud Run / GKE |
| **金流** | 綠界 NewebPay + 電子發票 | — |

### 3.1 Mr.Pet 電商平台（C端）

#### 3.1.1 商城功能
- [ ] 商品上架：寵物用品、食品、體驗券
- [ ] 商品分類與搜尋
- [ ] 購物車與結帳流程
- [ ] 訂單管理與物流追蹤
- [ ] 庫存管理（後台）

#### 3.1.2 會員系統
- [ ] 註冊 / 登入（LINE / Google / Apple SSO）
- [ ] 會員資料管理
- [ ] 寵物檔案（可連動至 PetRisk.AI 病歷）

#### 3.1.3 PetPoint 紅利積分
- [ ] 消費累點（比例由後台設定）
- [ ] 點數查詢與明細
- [ ] 獸醫端折抵 API（跨系統查詢餘額）
- [ ] 點數到期提醒

#### 3.1.4 金流整合
- [ ] 綠界 NewebPay 信用卡 / 超商 / ATM 繳費
- [ ] 電子發票自動開立（Turnkey 上傳財政部）
- [ ] 退款與作廢流程

---

### 3.2 PetRisk.AI 獸醫端 SaaS（B端）

#### 3.2.1 多租戶管理
- [ ] 診所註冊與帳號開通
- [ ] 獸醫師帳號管理（所內權限）
- [ ] 獨立 Workspace（資料完全隔離）

#### 3.2.2 病患管理
- [ ] 病患登錄（透過 Token ID 去識別化）
- [ ] 飼主資料綁定（SSO 連動）
- [ ] 就診歷程 Timeline
- [ ] 病歷資料夾管理

#### 3.2.3 醫療影像上傳
- [ ] 支援格式：DICOM、JPEG、PNG
- [ ] 影像類型：X 光、CT、腹部超音波
- [ ] 上傳至 GCS 加密儲存
- [ ] 影像預覽與縮圖

#### 3.2.4 AI Second Opinion
- [ ] 影像自動分析（Vertex AI）
- [ ] 診斷建議與機率預測
- [ ] **可解釋性**：引用台大獸醫系期刊論文出處
- [ ] 獸醫師 Approve / 修正機制
- [ ] Approve 後同步寫入病歷與飼主端

#### 3.2.5 結帳與 PetPoint 折抵
- [ ] 診療費用輸入
- [ ] 即時查詢飼主 PetPoint 餘額（跨系統 API）
- [ ] 點數折抵計算
- [ ] 現金 / 刷卡收款記錄（診所自行收款）
- [ ] 發票開立整合（可選）

#### 3.2.6 報表與統計
- [ ] 診所營業報表
- [ ] 病患統計
- [ ] AI 使用次數統計

---

### 3.3 共享基礎設施

#### 3.3.1 SSO 身份驗證
- [ ] OAuth 2.0 + OpenID Connect
- [ ] 支援 LINE Login、Google、Apple Sign-In
- [ ] JWT Token 跨系統傳遞
- [ ] 登入狀態同步（單點登出）

#### 3.3.2 Token ID 去識別化服務
- [ ] 飼主真實身分 ↔ Token ID 一對一映射
- [ ] 醫療端僅能看到 Token ID，無法反查真實身分
- [ ] 獸醫間病歷共享時隱藏診斷醫師資訊
- [ ] 飼主授權紀錄（可查詢誰看過自己的資料）

#### 3.3.3 資料儲存架構

| 資料類型 | 儲存位置 | 隔離等級 |
|---------|---------|---------|
| 電商訂單 / 商品 | Shared PostgreSQL | 標準商業資料 |
| 會員帳號 / PetPoint | Shared PostgreSQL | 個資保護 |
| 醫療病歷（去識別化） | De-identified DB | 機敏醫療資料 |
| 醫療影像 | GCS（加密 + IAM） | 機敏醫療資料 |
| 期刊論文向量 | PGVector | 知識庫 |

## 四、安全與合規設計

### 4.1 個資保護
- **去識別化**：所有醫療紀錄以 Token ID 儲存，真實身分獨立加密存放
- **最小權限**：獸醫僅能看到自己診所的病患資料
- **存取紀錄**：所有資料查詢保留 Audit Log

### 4.2 法律文件
- [ ] 隱私條款（Privacy Policy）
- [ ] 使用者服務條款（Terms of Service）
- [ ] 免責聲明（Second Opinion 非正式診斷）
- [ ] 個資同意書（寵物醫療資料使用授權）

### 4.3 資安標準
- SSL/TLS 全站加密
- 資料庫加密靜態儲存（TDE）
- API 速率限制與 WAF
- 定期漏洞掃描

## 五、MVP 範圍與里程碑

### 5.1 MVP 功能範圍（8 月上線）

為控制成本與時程，MVP 聚焦以下核心功能：

**Mr.Pet 電商 MVP**
- 商品上架與購買（10 個 SKU 內）
- LINE / Google 登入
- 綠界金流 + 電子發票
- PetPoint 累點（消費 1 元 = 1 點）

**PetRisk.AI MVP**
- 單一診所帳號（暫不開放自行註冊）
- 病患上傳 X 光片（JPEG）
- Vertex AI 基礎影像分析
- Second Opinion 文字報告（含論文引用）
- 獸醫師 Approve 機制
- PetPoint 折抵查詢（API 串接）

### 5.2 開發時程

| 階段 | 時間 | 交付項目 |
|------|------|---------|
| **Phase 1** | 5 月 ~ 6 月中 | 系統架構設計、資料庫設計、SSO 串接、綠界金流 |
| **Phase 2** | 6 月中 ~ 7 月中 | Mr.Pet 電商前台 + 後台、PetPoint 引擎、商品上架 |
| **Phase 3** | 7 月中 ~ 8 月初 | PetRisk.AI 獸醫端 Dashboard、影像上傳、Vertex AI 整合 |
| **Phase 4** | 8 月初 ~ 8 月中 | 兩系統串接測試、安全滲透測試、UAT |
| **Go-Live** | 8 月底 | 正式上線、種子診所導入（目標 3~5 間） |

### 5.3 上線後目標

| 指標 | 8 月 | 9 月 | 10 月 | 12 月 |
|------|------|------|-------|-------|
| 合作診所數 | 5 | 15 | 30 | 50+ |

## 七、風險與因應

| 風險 | 影響 | 因應措施 |
|------|------|---------|
| 獸醫公會接受度 | 高 | 與台大動物醫院 POC，取得公會理事長認可 |
| AI 診斷準確度 | 中 | 期刊論文 RAG 支撐可解釋性，明確標示為「輔助參考」 |
| 8 月時程壓力 | 高 | MVP 削減非核心功能，優先電商 + 基礎 AI 分析 |
| 醫療個資法規 | 高 | 去識別化設計、隱私條款、免責聲明完備 |
| 點數法規（電子票證） | 中 | PetPoint 設計為「折扣點數」非儲值，規避電子票證規範 |
