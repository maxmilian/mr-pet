### 2.4 本版範圍界線（明確移出的項目）

VetPoint 規格書共 37 節，本版不做完全部。以下**八項**明確移出，**此清單須列為合約附件**；規格第十六節（Redemption 狀態機）已由 V2、V3 涵蓋，其餘未列於本表、亦未見於 §2.3「對應規格節次」欄者，簽約前應逐節確認歸屬：

| 移出項目 | 規格書原文 | 本版實作 | 對營運的影響 |
|---------|----------|--------|-------------|
| **現金清算與付款** | Payable → Settlement → 付款登記 | **不做**。系統只產生雙方確認後的對帳結果 | 財務依對帳單自行匯款，系統不留付款狀態 |
| Partial Reversal | 部分反沖 + Admin Adjustment | 僅完整反沖（整筆作廢後重開） | 院所改單需整筆重來 |
| Statement 狀態機 | 六態 + 跨月 Adjustment + RECONCILED | 三態（DRAFT／CONFIRMED／CLOSED）+ 爭議標記；CLOSED 由人工於付款登記後標記 | 跨月調整以次月對帳單的調整列處理（調整列在 V5 範圍內） |
| Admin Control Center | 11 模組 | 3 模組 | 報表、批次工具、進階設定 Phase 2 補 |
| RBAC 角色 | 五角色 | 三角色（Mr.Pet Admin／院所管理者／院所操作員） | 財務與稽核角色暫由 Admin 兼任 |
| 防弊告警 | 6 條規則 | 3 條核心規則 | 涵蓋短時間重複核銷、單筆異常高額、單日超限 |
| Clinic 剩餘醫療費 | 第 15 節 | **不做**。折抵後的剩餘醫療費由院所既有收費流程處理，系統不記錄 | 系統只掌握折抵金額，不掌握該次就診總額 |
| 驗收案例 | 第 36 節完整 | 主流程 + 關鍵邊界（見下） | — |

**驗收基準**：

> **驗證環境與時點**：基準 1、2、4、5、6 於 **UAT 環境以測試資料驗收**，完成即屬功能驗收通過；基準 3 性質為生產資料的連續觀測，於 **§八 上線後試營運期間**驗證，不構成功能驗收的前提。

1. 同一飼主同時在兩家院所發起 Quote → 點數不得超扣
2. Confirm 重送相同 Idempotency Key → 只成立一筆
3. Ledger 重算餘額 = Wallet balance（試營運期間連續 **10 個營業日**零差異）
4. 完整反沖後，Wallet、Ledger、對帳明細三方一致；對帳單已 CONFIRMED／CLOSED 後才發生的反沖，以次月調整列呈現，當期對帳單金額不追溯變更
5. 月度對帳單金額 = 當月核銷明細加總；院所端確認後轉 CONFIRMED；爭議可標記、附理由，結案後留存完整軌跡
6. 訂閱扣款成功 → 自動發點；暫停／取消 → 停止發點

## 三、交付節奏

### 3.1 依賴關係

```
S1 API 契約 ──┬──> ① 電商（C4 接 Pet ID／Consent）
              └──> ② 點數（V0 Schema 依附共用層）

S2 Identity ────> C2 訂閱結帳、V6 院所端登入
S4 Clinic ID ───> V5 雙向對帳（對帳對象）
S6 RBAC/Audit ──> V6 院所端、V9 防弊告警
S7 Notification ─> C3 扣款通知、C5 到貨通知、V3 核銷確認
S11 綠界 ───────> C2 定期定額
C2 訂閱扣款 ────> V10 自動發點
```

**唯一的硬阻塞是 S1（API 契約）**。契約定稿後電商與點數兩線可並行。
