**不在本報價內**：
- 引擎 ②（VetPoint）→ 見 [VMCS 報價 v1.0](2026-09-04-vetpoint-vmcs-quotation.md)，NT$ 833,800

- 提案 v1.2 已涵蓋的 WooCommerce 商城本體

> **採 Thin Platform 策略**：共用層第一版只做三引擎當下真的會用到的能力，不預先建造無使用者的抽象層。理由與風險見影響分析文件 §4.2。

## 三、交付節奏建議

嚴格「共用層全做完再做引擎」會把 VMCS 方案 B 的 **11/28 Stage 1 上線**整個往後推。建議三段交付，讓共用層與引擎交錯：

### Phase 0 — 平台地基（4 週 / 22 人日 / NT$ 246,000 未稅）

範圍：S1、S2、S3、S4、S10、S13

- 交付：Identity 對映、Global Pet ID、Clinic ID、Config 中心、API 契約與接入文件
- **完成後 VMCS 才可正式動工**（VMCS W1 依附共用層 Schema）
- 這是唯一必須「先做完」的部分，其餘共用層元件隨引擎需求接續

### Phase 1 — 引擎 ① 商業閉環（7 週 / 31 人日 / NT$ 314,000 未稅）

範圍：S5（Consent）、S7（Notification）、S11（Adapter）、E1、E2、E3、E7、E8 主流程測試

- 完成後可跑通：訂閱下單 → 付款（信用卡／轉帳）→ 權益開通 → 月光盒內容揭露 → 會員與 Pet Profile 建檔
- 與 VMCS Stage 1 可**並行推進**（共用層地基已在 Phase 0 完成）

### Phase 2 — 醫療動線與治理（7 週 / 35 人日 / NT$ 348,000 未稅）

範圍：S6（RBAC + Audit）、S8（Storage）、S9（Event）、S12（Observability）、S14、E4、E5、E6、E8 餘量

- 完成後可跑通：搜尋院所 → 線上預約 → 確認簡訊 → 看診 → 報告 Email → 會員中心查閱（含 second opinion）
- 需與引擎 ③ 的產出格式對齊；若 ③ 尚未上線，E6 先支援獸醫上傳的影像與診斷報告

> 三階段合計 88 人日／NT$ 908,000，加計 10% 專案管理費後與 §2.5 相同（NT$ 998,800 未稅）。

## 七、前提假設與不含項目

### 7.1 假設

1. 引擎 ① 前台仍以 **WordPress + WooCommerce** 為載體（提案 v1.2 §2.2）。若因共用層上移而改為自建前台，E1–E7 需重估，工作量預期增加 30–50%
2. 共用層部署於 **GCP Cloud Run + Cloud SQL PostgreSQL**，費用由客戶 GCP 帳號承擔
3. 身份層沿用 **Clerk**，本報價含串接與對映，不含自建 IdP
4. 簡訊供應商由客戶開戶（三竹或 every8d），**簡訊費用由客戶自付**
5. 全部介面為 **Web（RWD）**，不含原生 App——與客戶「全程於網頁中進行」一致
6. 設計稿由客戶提供或沿用 `mrpet.tw` 設計規範，不含獨立 UI/UX 設計工時
7. 引擎 ③ 的報告資料結構由客戶或第三方提供契約；E6 依該契約呈現，不含 AI 模型開發

### 7.2 不含項目

| 項目 | 說明 |
|------|------|
| 引擎 ③ PetRisk.ai CDS 開發 | AI 模型、RAG 語料、向量庫建置均未含 |
| 院所行事曆時段庫存 | 見 §2.6 選配 |
| 院所既有 PMS 整合 | Adapter 僅預留擴充點 |
| 農業部寵物晶片號介接 | Global Pet ID 為平台內部識別，晶片號介接待確認可行性 |
| 醫療法／個資法法律意見 | 建議客戶另聘律師，與 VMCS §6 法遵議題同批處理 |
| 金融級外部稽核／滲透測試 | 可另行安排第三方 |
